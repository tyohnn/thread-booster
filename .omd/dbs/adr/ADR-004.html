수집은 SSR JSON 파싱만 쓰고 DOM 스크래핑은 폐기한다

Context

2026-08-08 이전에는 브라우저를 띄워 DOM을 긁었다. 그 방식은 카운트가 반올림되고, 조회수를 못 얻고, 체인을 잘못 묶었다. 실제로 체인 구성의 80%가 틀렸다. Threads는 퍼머링크 HTML의 <script type="application/json"> 안에 게시물 데이터를 통째로 보낸다.

Decision

  • 수집은 퍼머링크 SSR JSON 파싱으로 한다. 로그인이 필요 없다
  • DOM 수확기(extract_chain.js, harvest_runner.js)는 더 이상 쓰지 않는다
  • 예외: 신규 글 발견은 프로필 피드 페이지네이션이 필요하고 여기에는 로그인 세션이 든다

Consequences

  • 체인 구성은 SSR 페이로드의 스레드 구조를 근거로 재구축했다
  • 구 CSV·구 JSON은 시점 스냅샷으로 보존한다 (→ POL-004)

Alternatives considered

Notion 본문에 해당 섹션 내용 없음.

근거

  • 카운트가 정수로 나온다 (화면 표기는 2유효숫자 반올림)
  • 조회수를 얻을 수 있다. 초반 유지율은 이걸로 처음 측정됐다
  • 로그인이 없으므로 계정에 이력이 남지 않는다. 2026-08-08 기준 1,506요청 실패 0건

위험

Threads의 SSR 페이로드 구조가 바뀌면 파서가 깨진다. 파서를 한 파일(ssr.mjs)로 격리해 둔 이유다.
