로컬 스토어는 DuckDB 파일 하나로 간다

summary
로컬 스토어는 DuckDB 파일 하나로 간다. REL-001(F-007)의 전제다.
영역
데이터 모델
결정일
2026-08-09

Context

로컬 단독 실행이고 쓰기는 수집할 때만, 읽기는 집계·정렬·조인이 대부분이다. 관측 시계열은 append-only로 계속 자란다. F-007(로컬 스토어 빌드)는 엔진 선택이 없으면 착수할 수 없다.

Decision

DuckDB 파일 한 개를 스토어로 쓴다. 원본 JSONL은 그대로 보존하고, DuckDB는 언제든 재생성 가능한 파생물로 취급한다.

채택일: 2026-08-09 (REL-001 문서 잠금).

Consequences

  • 정규화 단계가 DuckDB 적재까지 책임진다 (F-007)
  • 스키마 변경 시 마이그레이션 대신 전체 재생성한다. 원본이 JSONL로 남아 있어 가능하다
  • SQLite는 기각한다 — 이 규모에서 충분할 수 있으나, 유지율·시점별 성장·유형별 중앙값 질의가 컬럼 지향에 더 맞다

Alternatives considered

대안평가
SQLite익숙하고 안정적이지만 집계·분석 함수가 약하다. 이 규모(2만 행)에서는 실질 차이가 크지 않을 수 있으나 DuckDB를 채택한다
JSON 파일 직접 읽기지금 방식. 매번 전체를 메모리에 올려야 하고 조인이 코드로 흩어진다

근거

  • 집계·윈도우 함수가 필요한 질의(유지율 분포, 시점별 성장, 훅 유형별 중앙값)가 대부분이라 컬럼 지향이 맞는다
  • JSON·Parquet을 직접 읽을 수 있어 정규화 산출물을 그대로 적재한다
  • 파일 하나라 백업·삭제·재생성이 단순하다

미결 (REL-001 비차단)

  • 대시보드가 DuckDB를 서버에서 읽을지, 브라우저(WASM)로 내려보낼지 — v1.0 대시보드 설계 시 재논의. CLI 적재만 하는 REL-001에는 영향 없다
