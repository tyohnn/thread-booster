DM-001

REL-001 파이프라인 스토어 계약

stage
accepted
specType
data-model
summary
accounts.json · raw JSONL · normalized · DuckDB 단일 파일의 입출력과 append-only 관측 불변식.

Contract

pnpm data:refresh는 활성 계정을 순차 수집하고, raw를 정규화한 뒤 DuckDB 파일을 전체 재생성한다. 원본 권위는 JSONL이며 DuckDB는 파생물이다 (ADR-002).

Entities

  • Account — 레지스트리 행 (accounts.json): handle, alias?, active, last_fetched_at?
  • RawObservation — append-only JSONL 라인 (퍼머링크 수집 결과)
  • Post / Chain — 정규화 산출물
  • Metric — (post_id, observed_at) 시계열; 덮어쓰기 금지
  • Retention — 체인 초반 유지율 등 (POL-003)
  • Store — DuckDB 파일 1개 (accounts, chains, posts, metrics, retention 테이블)

Fields

엔티티핵심 필드
Accounthandle (PK), active, last_fetched_at
Postpost_id, chain_id, account, position, permalink
Metricpost_id, observed_at, views?, likes? (결측=NULL, 0 아님)
Retentionchain_id, early_retention? (2번/1번), n 근거

Invariants

  • 동시에 한 계정만 수집 (POL-001)
  • metrics는 append-only; 동일 (post_id, observed_at) 재기록 시 멱등 또는 거부
  • 조회수 결측을 0으로 채우지 않는다 (POL-003)
  • 단일 글 체인은 유지율 계산 제외
  • 원문 raw는 git에 올리지 않는다 (POL-002)
  • 스키마 변경 시 DuckDB는 마이그레이션 대신 전체 재생성

Acceptance

  • 한 명령으로 raw→normalized→DuckDB까지 완료
  • 스토어에 계정 ≥ 3, 체인 ≥ 1000
  • 같은 post에 서로 다른 observed_at 행이 공존 가능
  • JSONL만으로 스토어 재생성 가능
